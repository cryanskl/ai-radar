# 01 产品策略

## 1. 产品命题

全球 AI 信息高速增长，但信息分散在官方博客、论文平台、GitHub、模型与产品网站、媒体、社交平台和社区中。用户面对的核心问题不是“网上没有内容”，而是：

- 不知道今天真正重要的变化是什么。
- 同一事件由多个来源重复报道，难以判断哪条是原始来源。
- 新闻、模型、论文、代码、产品、Prompt 和 Skill 彼此割裂。
- 英文和中文信息圈存在时间差、翻译差和关注差。
- 热门榜、评测榜和推荐经常缺少明确口径。
- 旧新闻很快沉没，无法沉淀为可检索的长期知识。
- 通用搜索或聊天模型可以总结网页，却缺少稳定、版本化、可纠错的 AI 专题数据层。

AI Radar 的产品命题是：

> 广泛采集全球 AI 信号，以事件去重、双语本地化、实体档案、知识图谱、透明排名和开放数据，把“信息很多”转化为“今天看得完、以后找得到、结论查得回”。

## 2. 愿景与定位

### 2.1 愿景

成为全球 AI 生态的开放双语信息层：任何人都能持续了解变化、追溯来源、连接知识并复用公开数据。

### 2.2 定位

AI Radar 由三层组成：

1. 全球 AI 实时信息雷达。
2. 结构化长期资料库与知识图谱。
3. 基于本站证据的搜索与研究 Agent。

它不是：

- 只转载标题的链接导航。
- 只做编辑观点的 AI 媒体。
- 只按一个综合分排序的模型榜。
- 只服务单一厂商或单一工具的社区。
- 通过复制第三方全文构建的 SEO 内容农场。
- 替用户直接运行所有模型的聚合调用平台。

## 3. 目标用户

### 3.1 核心用户：AI 深度用户

共同特征：

- 每周多次使用或研究 AI。
- 会根据新模型、产品、论文或工具调整工作流。
- 需要跨来源判断，而不是只看单条新闻。
- 愿意阅读数据、来源和方法说明。
- 可能同时跨越开发、研究、产品或创作角色。

典型人群：

- AI 与软件开发者。
- 研究者与研究工程师。
- AI 产品经理与创业者。
- 图像、视频、文字与音频创作者。
- 技术投资、战略和行业观察者。

### 3.2 角色视角

角色不是底层内容类型，而是跨内容筛选方式：

| 角色 | 主要任务 |
|---|---|
| Developer | 关注模型、API、GitHub、Agent、Skill、配置和代码能力 |
| Researcher | 关注论文、机构、代码实现、Benchmark 与研究主题 |
| Creator | 关注图像、视频、音频、产品、Prompt 和工作流 |
| Product | 关注产品发布、定价、能力、竞争格局和用户趋势 |
| Founder | 关注行业事件、公司、市场、开源生态与商业变化 |

### 3.3 非首要用户

完全不了解 AI、只偶尔使用单一聊天产品的普通用户不是 Alpha 首要目标。产品应保持可读，但不通过降低数据透明度来追求所有人群。

## 4. 核心用户任务

### 4.1 每日发现

> 今天 AI 世界发生了什么？如果只看十条，应该看什么？

产品结果：

- Today’s Brief。
- Latest、Trending、Featured 分流。
- 事件去重。
- 中英文呈现。
- 原始来源与多来源对照。

### 4.2 持续追踪

> 某个模型、公司、产品或研究方向最近发生了什么变化？

产品结果：

- 实体档案。
- 事件时间线。
- 相关论文、GitHub、Benchmark、Prompt 与 Skill。
- 局部知识图谱。

### 4.3 比较与选型

> 哪个模型在当前场景更强、更快或更便宜？这个榜单为什么这样排？

产品结果：

- 可追溯 Benchmark。
- 价格与配置。
- 场景榜而不是唯一总榜。
- 方法说明、时间窗口和数据时间。

### 4.4 搜索与研究

> 帮我总结过去半年某一主题的关键变化，并给出证据。

产品结果：

- 跨中英文检索。
- Search 快速找记录。
- Ask 基于本站数据综合。
- 每个关键结论链接来源。

### 4.5 获取可复用资产

> 有哪些值得使用的 Prompt、Skill、Guide 或 GitHub 项目？

产品结果：

- 许可证清晰的资产档案。
- 兼容环境、作者、来源和更新时间。
- 与模型、产品和工作流关联。

## 5. 产品价值

### 5.1 对读者

- 一站看到全球 AI 变化。
- 用双语降低信息差。
- 通过事件聚类减少重复。
- 通过来源与方法降低误判。
- 通过图谱发现跨类型关系。
- 通过历史档案长期复用。

### 5.2 对开发者和研究者

- 使用开放 API 和数据快照。
- 复现排名与趋势。
- 贡献采集器、Schema、关系和纠错。
- 自部署 Apache-2.0 代码。

### 5.3 对来源方

- 明确展示原始来源与原文链接。
- 不以复制全文替代原站。
- 将多来源放入同一事件上下文。
- 提供更正、撤回与权利联系入口。

## 6. 差异化

AI Radar 的差异不是“比别人抓更多网页”，而是以下能力的组合：

1. 全球信息与完整中英文体验。
2. 文章去重为事件，事件沉淀到实体时间线。
3. 新闻、模型、论文、产品、GitHub、Prompt、Skill 和 Guide 互相连接。
4. Latest、Trending、Featured 和各类榜单使用不同透明口径。
5. Search 与有来源 Agent 共享同一版本化数据层。
6. 代码、Schema、方法和允许开放的数据可复用。
7. 公开更正、撤回、翻译状态和已知限制。

## 7. 产品原则

### 7.1 后台尽可能全，首页必须克制

“All in one”表示一个站内能找到全部类型，不表示一个屏幕塞入全部内容。

### 7.2 原始来源是一等公民

用户能够在每条记录中识别来源、时间、语言、核验状态和原文链接。

### 7.3 允许不下结论

证据不足、测试条件不一致或结果接近时，产品明确说明限制，不强行选第一名。

### 7.4 事实、翻译、编辑判断分层

- 事实来自可追溯来源。
- 翻译显示机器或人工状态。
- 编辑精选与“为什么重要”明确标识。
- AI 摘要不冒充原文。

### 7.5 关系必须有证据

知识图谱边不是模型随意联想；它需要关系类型、来源、时间、置信度和审核状态。

### 7.6 开放不等于无边界复制

只开放本站有权许可的字段。第三方内容保留原权利，不被本站许可证覆盖。

### 7.7 Alpha 诚实

数据覆盖、翻译、历史回填、排名和自动化仍在完善时，对外明确标示。

## 8. Public Alpha 范围

### 8.1 必须交付

- 八个正式内容域都有真实数据、双语列表和详情。
- 桌面与移动导航可访问全部内容域。
- 首页包含每日摘要、重点事件、主信息流和内容域速览。
- 事件可关联多个来源，并支持基础合并与拆分。
- 主要实体拥有时间线、正反向关系和局部图谱。
- Search 与基于本站数据的 Ask。
- Latest、Trending、Featured 分离。
- 中英文 RSS 与中英文邮件日报。
- 无登录本地收藏和偏好。
- 最小编辑后台。
- 版本化只读公共 API。
- 开放数据快照、Schema、校验值、许可证和镜像。
- 公开 Trust Center、方法、来源、纠错和已知限制。

### 8.2 深度分级

所有内容域在产品上成立，但自动化程度不同。不得用占位符或空页面伪造覆盖。尚未自动化的域使用少量真实、人工精选且权利清晰的内容。

### 8.3 后续阶段

- 全局知识图谱。
- Obsidian 导出或同步。
- 更广泛来源语言。
- 账号、跨设备收藏和团队空间。
- 高级个性化和通知。
- 更多可复现 Benchmark。
- 企业自定义 Radar。

## 9. 商业模式

### 9.1 当前阶段

- 优先验证用户是否持续回来。
- 不让赞助或联盟关系改变自然排序。
- 商业关系明确披露。
- 免费公开网页、基础搜索、RSS、代码和许可范围内的数据。

### 9.2 长期模式

开放基础设施 + 官方托管服务。

潜在付费能力：

- 高频更新与更长历史窗口。
- 高级研究 Agent。
- 个性化订阅与提醒。
- 高配额 API 与批量导出。
- 团队空间和私有资料。
- 趋势监控与自定义 Radar。
- 企业来源白名单、审计和 SLA。

## 10. 成功指标

### 10.1 增长主指标

Monthly Qualified Page Views。

必须排除：

- 机器人与爬虫。
- 页面预加载。
- 异常重复刷新。
- 后台与 API 流量。
- 为制造 PV 而拆分的事件页面。

### 10.2 产品健康指标

7-Day Returning Reader Rate。

它验证用户是否认为 AI Radar 值得持续回来，而不是只从搜索引擎偶然进入一次。

### 10.3 价值行为

- 打开原始来源。
- 展开事件的多个来源。
- 切换中英文。
- 搜索和 Ask。
- 收藏与再次访问。
- 订阅 RSS 或邮件。
- 复制 Prompt。
- 打开 GitHub 或论文。
- 使用模型比较与方法说明。

### 10.4 内容健康指标

- 重复事件率。
- 缺失来源率。
- 翻译纠错率。
- 过期价格和榜单比例。
- 自动发布后撤回比例。
- 首页来源集中度。
- 没有证据的关系数量。

## 11. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 内容很多但噪音更大 | 精选/全量分层、事件聚类、首页克制 |
| 双语产生事实漂移 | 同一事实记录、本地化分层、翻译状态与重点复核 |
| 自动摘要幻觉 | 只依据来源、关键字段校验、失败不发布 |
| 榜单变成伪科学 | 分对象口径、公开方法、允许不下结论 |
| 第三方权利不清 | 逐记录权利状态、开放导出过滤、原文回链 |
| 一人维护失控 | 按风险分级自动化、最小后台、人工只处理高价值队列 |
| 八个域变成空壳 | 每个域必须有真实数据与详情；减少自动化而不是放占位符 |
| 历史回填拖垮上线 | 先建 1,000–3,000 个关键事件骨架，持续增量回填 |
| 搜索 Agent 失去可信度 | 只使用版本化本站数据，答案带来源和时间 |
| 开源与商业冲突 | Apache-2.0 代码、CC BY 4.0 本站数据、托管能力收费 |
