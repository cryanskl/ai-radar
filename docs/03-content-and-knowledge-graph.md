# 03 内容模型与知识图谱

## 1. 设计目标

AI Radar 的底层不是“所有东西都是文章”，而是由来源条目、事件、实体、本地化内容和有证据关系组成的知识系统。

目标：

- 同一事件由多个来源支撑，而不是重复展示。
- 同一实体的中英文版本共享事实。
- 新闻能够沉淀到模型、产品、公司和研究时间线。
- 用户能看到正向链接、反向链接和局部关系图。
- Search、Ask、排行榜、开放 API 和数据快照使用同一事实层。
- 更正、撤回和版本变化可以传播到下游。

## 2. 核心对象

| 对象 | 作用 |
|---|---|
| Source | 信息源定义：官方站、论文平台、媒体、社区等 |
| Source Item | 从一个来源采集的一条原始记录 |
| Event | 多个来源描述的同一现实事件 |
| Entity | 可长期识别和连接的对象 |
| Localized Content | 同一事实记录的中文或英文呈现 |
| Relation | 对象之间有类型、有证据的连接 |
| Evidence | 支撑事件、关系、字段或排名的数据来源 |
| Metric Observation | 某对象在某时间的可比较指标 |
| Editorial Note | 明确标记的本站判断 |
| Correction | 对已发布内容的更正 |
| Tombstone | 记录撤回、删除或不可继续使用 |

## 3. 实体类型

Alpha 的正式实体类型：

| 类型 | 示例字段 |
|---|---|
| Model | 厂商、版本、模态、上下文、价格、可用渠道 |
| Paper | 标识符、作者、机构、摘要、主题、许可证 |
| Product | 厂商、类别、定价、平台、支持模型 |
| Repository | Owner、语言、Stars、Forks、Release、许可证 |
| Prompt | 作者、适用模型、任务、参数、许可证 |
| Skill | 作者、兼容工具、安装方式、权限、安全状态、许可证 |
| Guide | 作者、难度、任务、相关实体、更新时间 |
| Organization | 名称、地区、类型、官网、相关对象 |
| Person | 姓名、公开角色、机构、相关工作 |
| Benchmark | 任务、数据集、指标、版本、方法 |
| Topic | Agents、Coding、Image、Video、Safety 等 |

Person 只保存产品所需的公开专业信息，不建设个人画像。

## 4. Source Item 与 Event

### 4.1 Source Item

Source Item 表示“某来源发布了什么”，保留来源事实：

- 稳定 ID。
- 来源。
- 原始 URL 与 canonical URL。
- 原始标题。
- 原始语言。
- 作者（可用时）。
- 原始发布时间。
- 本站发现时间。
- 原始更新时间。
- 来源提供的标识符。
- 内容指纹。
- 抓取状态。
- 权利状态。
- 原始响应引用（仅内部，按权利与保留策略管理）。

### 4.2 Event

Event 表示“现实中发生了什么”：

- 稳定 ID。
- 事件类型。
- 规范标题。
- 规范摘要。
- 首次发生时间。
- 最后更新时间。
- 状态：传闻、已确认、已更正、已撤回等。
- 主要来源。
- 关联 Source Items。
- 关联实体。
- 编辑重要性。
- 聚类置信度和审核状态。

### 4.3 聚类原则

以下条件共同决定是否属于同一事件：

- 主体一致。
- 动作一致。
- 对象一致。
- 时间接近。
- 版本或产品名称一致。
- 来源之间存在直接引用或指向同一官方材料。

不能只凭标题相似度合并。

### 4.4 合并与拆分

- 自动系统只能提出聚类候选。
- 高置信且低风险候选可自动进入普通流。
- 首页头条、价格变化、法律政策和争议事件需要复核。
- 管理后台必须支持合并与拆分。
- 合并和拆分记录进入审计日志。
- URL 和外部引用使用稳定 Event ID，不因合并而失效；必要时建立重定向。

## 5. 双语与本地化

### 5.1 单一事实，多语言呈现

每个事件或实体只有一份语言无关事实记录，中文和英文是 Localized Content：

- 原始标题。
- 原始语言。
- 中文规范标题。
- 英文规范标题。
- 中文摘要。
- 英文摘要。
- 中文编辑说明。
- 英文编辑说明。
- 翻译生成方式。
- 翻译审核状态。
- 最后本地化时间。

### 5.2 状态

- Original。
- AI translated。
- Reviewed。
- Official translation。

### 5.3 不变量

- 翻译不能修改价格、日期、版本、参数和主体。
- 中文和英文可以本地化表达，但必须指向同一事实与来源。
- 某语言未完成时不生成假装完整的空白 SEO 页面。
- 修正事实后，所有语言版本进入待同步状态。

## 6. 关系模型

### 6.1 关系结构

每条 Relation 至少包含：

- Relation ID。
- 源对象 ID 与类型。
- 关系类型。
- 目标对象 ID 与类型。
- 方向。
- 有效开始与结束时间（适用时）。
- Evidence IDs。
- 首次发现时间。
- 最后核验时间。
- 置信度。
- 审核状态。
- 创建方式：自动、编辑、投稿。
- 权利与公开状态。

### 6.2 Alpha 关系词表

| 源 | 关系 | 目标 |
|---|---|---|
| Paper | INTRODUCES | Model / Method |
| Repository | IMPLEMENTS | Paper / Model |
| Product | USES | Model |
| Benchmark | EVALUATES | Model |
| Prompt | WORKS_WITH | Model / Product |
| Skill | SUPPORTS | Product / Agent Tool |
| Guide | EXPLAINS | Entity |
| Event | ANNOUNCES | Entity |
| Event | UPDATES | Entity |
| Event | CHANGES_PRICE_OF | Model / Product |
| Event | DEPRECATES | API / Model / Product |
| Organization | DEVELOPS | Model / Product |
| Person | AFFILIATED_WITH | Organization |
| Entity | TAGGED_WITH | Topic |

关系词表需要版本化。新增关系前先确认是否能被清晰解释和验证，避免同义关系泛滥。

### 6.3 关系证据

关系必须至少指向一条 Evidence：

- 官方文档。
- 论文。
- 仓库清单或代码许可证。
- 产品文档。
- 可复现 Benchmark。
- 经过审核的来源条目。

只由模型语义推断、没有证据的关系不得进入公开图谱。

## 7. 正向链接、反向链接与局部图

### 7.1 正向链接

显示当前对象主动连接的对象。例如：

- 论文提出哪些模型。
- 产品使用哪些模型。
- 仓库实现哪些论文。
- Skill 支持哪些工具。

### 7.2 反向链接

由相同关系反向查询得到：

- 哪些产品使用这个模型。
- 哪些仓库实现这篇论文。
- 哪些 Guide 解释这个 Skill。
- 哪些事件改变了这个产品。

反向链接不是单独手工维护的副本，必须由关系数据计算，避免双边不一致。

### 7.3 局部图谱

Alpha 显示当前实体一到两跳关系：

- 默认只显示高置信、已公开关系。
- 可以按关系类型过滤。
- 节点数量设可读上限。
- 超出上限时优先重要和近期关系。
- 提供等价文本列表。
- 不将全局力导向图作为 Alpha 硬性范围。

## 8. 时间线

实体详情页的 Timeline 由 Event 与 Metric Observation 生成：

- 首次发布。
- 版本更新。
- API 上线或弃用。
- 价格变化。
- Benchmark 更新。
- 重要论文。
- GitHub Release。
- 重大行业事件。

时间线按事实发生时间排序，同时显示本站发现或最后核验时间。用户必须能区分“事情何时发生”和“本站何时收录”。

## 9. 指标观察

可变化的数字不能覆盖历史值，使用 Metric Observation：

- 对象 ID。
- 指标定义与版本。
- 数值与单位。
- 观察窗口。
- 观察时间。
- 来源。
- 采集方式。
- 是否估算。
- 质量状态。

适用：

- 模型价格。
- Benchmark 分数。
- GitHub Stars 与增长。
- 产品价格。
- 社区热度。
- 榜单位置。

## 10. 编辑内容分层

### 10.1 事实摘要

只概括来源支持的事实，不加入站长评价。

### 10.2 Why It Matters

本站编辑判断，必须明确标记，并链接证据。

### 10.3 Featured

编辑选择，不等同于客观热度或自动排名。

### 10.4 Daily Brief

由同一组事件生成中文和英文两个本地化版本，事实集合与排序一致，表达可以本地化。

## 11. 标识符与 URL

- 所有核心对象使用稳定、语言无关 ID。
- 中文和英文路由共享同一 ID。
- Slug 可修改，不作为外键。
- 合并实体保留重定向映射。
- 删除或撤回不复用旧 ID。
- 公共 API 和开放快照暴露稳定 ID。

## 12. 更正、撤回与版本

### 12.1 更正

记录：

- 对象 ID。
- 变更字段。
- 原因。
- 证据。
- 生效时间。
- 替代版本。

### 12.2 Tombstone

记录：

- 对象 ID。
- 撤回类型。
- 生效时间。
- 可公开原因码。
- 是否有替代记录。

### 12.3 下游传播

- 网站不再展示被撤回正文。
- Search 与 Ask 不把撤回记录作为当前事实。
- API 返回明确状态。
- 开放数据增量包含更正与 Tombstone。
- 未来完整快照反映最新有效状态。

## 13. 权利与隐私字段

每个可公开对象至少包含：

- rights_status。
- source_license（可用时）。
- redistribution_scope。
- attribution。
- original_url。
- reviewed_at。

公开发行版只导出允许的字段。生产库中的原始抓取、内部审核、用户行为、邮箱、凭据和权利投诉资料不进入公开快照。

## 14. Alpha 不做

- 全局无限节点图。
- 图谱在线编辑器。
- 无来源自动关系。
- Obsidian 导出、导入或同步。
- 面向个人的关系画像。
- 用一个“相关度”字段替代明确关系类型。
- 直接使用第三方全文生成可再分发知识库。

## 15. 数据质量不变量

1. Event 至少有一个有效 Source Item。
2. 公开 Relation 至少有一个公开 Evidence。
3. 本地化内容必须指向同一事实对象。
4. 原始发布时间和本站发现时间不能混用。
5. 动态指标必须保留观察时间与来源。
6. 自动翻译、自动摘要和自动聚类必须有状态。
7. 撤回 ID 不得被新对象复用。
8. 公开快照中的字段必须通过权利过滤。
9. 反向链接由关系计算，不手工复制。
10. Search 和 Ask 不使用 internal_only 或 withdrawn 内容。
